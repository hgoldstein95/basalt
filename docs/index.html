Random generators you can
run and prove correct

Generators are the foundation of QuickCheck-style property-based testing; it is important that they are correct and efficient.

Basalt gives a single generator term a precise semantics that you can both run and reason about. We use a typeclass embedding to re-interpret the same generator term as both a standard sampler that you can draw values from and a formal probability distribution, represented using Lean's Mathlib.

A Basalt generator can be proved sound and complete (it produces every valid value and only valid values), almost-surely terminating, and cost-bounded, among other things.

Core Idea

Multiple Interpretations for the Same Generator

In Basalt a generator is not a value of some fixed generator type, it is a term that is polymorphic in the monad it runs in. The typeclass Gen bundles exactly the operations a generator needs, and the same term is then interpreted at whichever monad the task calls for.

When run at IO you can sample normally. When run at SPMF — a sub-probability mass function — you get a mathematical object you can write proofs about. For example, you can prove things about a generator's support, its total mass, the number of random choices it makes, etc. The code you run and the object you reason about are the same term.

A Worked Example

Using Basalt

A generator for binary search trees with keys in [lo, hi] — and the three theorems that pin down its behavior.

What you write
BST.lean 
-- what it means to be valid:
def isBST (lo hi : Int) : Tree Int -> Prop
  | leaf => true
  | node l x r =>
      lo ≤ x ∧ x ≤ hi ∧
      isBST lo (x - 1) l ∧
      isBST (x + 1) hi r

-- one term, polymorphic in the monad G:
def genBST [Gen G] (lo hi : Int) : G (Tree Int) := do
  if h : lo > hi then return leaf
  else pick
    (fun () => pure leaf)
    (fun () => do
      let x <- chooseInt lo hi (by omega)
      let l <- genBST lo (x - 1)
      let r <- genBST (x + 1) hi
      pure (node l x r))
partial_fixpoint
⊢
What you prove
  • sound_complete IsSoundAndComplete — the support is exactly the valid BSTs. Nothing invalid is ever produced; nothing valid is ever missed.
  • terminates IsAlmostSurelyTerminating — the generator halts with probability one. (This one is critical: mean offspring is exactly 1.)
  • cost_bounded IsCostBounded — an n-node tree costs at most 3n + 1 random choices to build.

Each law is a plain theorem named genBST.sound_complete, .terminates, .cost_bounded — proved by hand, checked by Lean.

Interpretations

Available Implementations of Gen

RandomChoice.choose is the only source of randomness; every combinator is built on it. That single interface is what lets one generator wear four different hats.

Plausible.Gen / IO Run it and get values — plug straight into a property-based testing loop.
SPMF A sub-probability mass function. Reason about the distribution and its support — this is where soundness, completeness, and termination live.
SPMF.Cost The distribution, plus a count of the random choices each draw makes — the ground truth for cost bounds.
GenStats.StatGen Seeded, fuel-guarded execution that counts choices — what #genstats draws from.
Key Ideas

Why use Basalt?

Run it or reason about it

There is no separate model to keep in sync. The generator you execute and the mathematical object you prove theorems about are one and the same term, interpreted at different monads.

A vocabulary of correctness

Five laws: soundness and completeness (IsSoundAndComplete), almost-sure termination (IsAlmostSurelyTerminating), cost bounds (IsCostBounded), and — for rejection samplers — filter-freedom (IsFilterFree) and productivity (IsProductive). These are plain predicates; a generator states and proves the ones that apply to it.

Evidence beside proof

#genstats draws hundreds of samples and prints distributions, diversity, and outcomes — then reports, right alongside, which laws are actually proved. A divergence count is evidence; a law is a proof, and the report never confuses the two.

Under the hood

Built on Cutting Edge Lean APIs

Recursive generators are defined by partial_fixpoint over a domain-theoretic order, and almost-sure termination is proved externally. Unlike standard Lean functions, Basalt generators are not required to terminate structurally.
